# SignalRank AI — Recruiter Dashboard User Guide

## Opening the dashboard

```bash
streamlit run app/streamlit_app.py
```

Opens at `http://localhost:8501`.

---

## Sidebar controls

### Run Pipeline

**Upload candidates.jsonl** — drag the organizer JSONL file into the uploader, then click **⚡ Rank Candidates**.

The pipeline runs in stages with a progress indicator:
1. Parsing candidates
2. Honeypot detection
3. Building semantic index (takes ~15-20s on first run)
4. Scoring the candidate pool
5. Generating explanations
6. Writing output files

A green banner confirms completion with the pipeline time.

### Load Results

If you've already run `rank.py` from the terminal, enter the path to `outputs/debug.json` and click **Load from file**. The dashboard loads without re-running the pipeline.

### Download buttons

Once results are loaded, download links appear for:
- **📥 Submission CSV** — the organizer-format file to submit
- **📄 Debug JSON** — full score breakdowns for all 100 candidates
- **📊 Eval Report** — structured evaluation report (JSON)

## Dashboard tabs

### 📋 Ranked Shortlist

Displays ranked candidates as cards showing:
- Rank badge (#1 in gold, #2 in silver, #3 in bronze)
- Job title, candidate ID, years of experience, company
- Color tags: `● active` (high behavioral score), location chip, `⚠ penalized`, `🚫 honeypot`
- Score pill (e.g. `0.9226`)
- Score bar (proportional to score)
- 1-2 sentence recruiter reasoning

**Filters** (click 🔧 Filters to expand):
- **Min score** — slider to exclude low-confidence candidates
- **Title contains** — text search on job title
- **Hide penalized** — exclude candidates with >5% penalty
- **Hide honeypots** — exclude flagged profiles (on by default)

**Show N** — select 10, 25, 50, or 100 candidates to display.

### 🔍 Candidate Detail

Select any candidate from the top-100 to see:

**Left panel:**
- Profile snapshot (title, company, experience, location, final score)
- Penalty warnings (if any)
- Recruiter reasoning paragraph

**Right panel:**
- Full 7-component score breakdown with color-coded bars
  - Green ≥ 0.80, amber 0.55–0.80, red < 0.55
- Penalty percentage and final score formula
- Behavioral sub-scores (recency, open-to-work, response rate, notice period, interview completion, GitHub activity)

### 📊 Evaluation

Shows the structured evaluation report (from `outputs/eval_report.json`):

- **Format checks** — spec compliance validation (6 checks)
- **Top-10 component averages** — bar chart of each scoring component
- **Baseline comparison** — how our model differs from a keyword-count baseline
  - Low overlap with baseline top-10 means our model genuinely discriminates differently
- **Error detection** — honeypots in top-100, wrong-domain high scorers, score compression warnings

> Run `python evaluation/eval.py --results outputs/debug.json --candidates data/raw/candidates.jsonl --json outputs/eval_report.json` to populate this tab.

### 📈 Score Distribution

Four visualizations:
1. **Score histogram** — distribution of final scores across top-100
2. **Radar chart** — 7-component score profile for the #1 ranked candidate
3. **Score vs YOE scatter** — final score plotted against years of experience
4. **Title bar chart** — how many of each job title appear in top-100

## KPI header metrics

| Metric | What it means | Good value |
|--------|--------------|------------|
| ML/AI in Top-10 | How many of top-10 are ML/AI engineers | ≥ 8/10 |
| Avg Top-10 Score | Mean final score of top-10 | Higher is better |
| Penalized Top-100 | Candidates with >5% penalty in top-100 | Should be low |
| Honeypots | Honeypot candidates in top-100 | Must be 0 (>10 = disqualification) |
| Ranked Candidates | Total candidates in output | Always 100 |

## Warning banners

**Honeypot risk** (orange) — appears if more than 10 honeypots are in the top-100. This triggers automatic disqualification by the organizer. Investigate the honeypot detection module if this appears.

**Pipeline complete** (green) — shows after a successful pipeline run with timing and output path.

## Interpreting the reasoning field

Each candidate card shows 1-2 sentences generated by the explainer:

```
NLP Engineer at CRED (9.0y exp); key skills: Python, sentence-transformers, FAISS, Scikit-learn;
production deployment evidence present. active this week; open to work; response rate 85%; 16d notice; location: Pune.
```

This encodes:
- **Title and company** — from profile snapshot
- **Years of experience** — from `years_of_experience` field
- **Top skills** — highest-proficiency matched skills
- **Production evidence** — whether career text contains deployment/scale keywords
- **Activity status** — recency of last login
- **Open to work** — boolean signal
- **Response rate** — recruiter response rate percentage
- **Notice period** — days
- **Location** — current location

## Common workflows

### Reviewing a specific candidate

1. Go to **🔍 Candidate Detail**
2. Select from the dropdown (candidates ordered by rank)
3. Review component breakdown to understand why they ranked where they did
4. Check behavioral sub-scores if you want to know their availability

### Finding candidates in a specific location

1. Go to **📋 Ranked Shortlist**
2. Expand **🔧 Filters**
3. The location tag is visible on each card — filter by title instead and scan location chips

### Exporting the shortlist

1. Use the **📥 Submission CSV** download button in the sidebar
2. Or use **📄 Debug JSON** for the full score breakdown (e.g., for a spreadsheet review)

### Understanding why a candidate was penalized

1. Select the candidate in **🔍 Candidate Detail**
2. Check the orange warning box for penalty reasons
3. See the **Penalty** percentage in the score breakdown panel
